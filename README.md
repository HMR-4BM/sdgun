# SDGun 二手交易市场工具

一个仅使用 Python 标准库实现的 SDGun 公开二手交易帖增量采集、检索与市场分析工具，
同时提供命令行爬虫和本地 Web 控制台。

> 本项目仅用于读取无需登录即可访问的公开信息。使用者应遵守目标站点条款、控制请求频率，并自行确认其使用方式符合当地法律法规。
##请使用中国大陆IP网段访问并使用。

## 主要功能

- 增量扫描与持续监控：使用 SQLite 游标续接，避免反复请求已扫描页面。
- 精准过滤：先检查页面标题，再解析目标帖子和评论，减少无效请求。
- 本地市场面板：展示供需、价格、交易状态、热门物品词和活跃发布者。
- 多关键词检索：支持任意词/全部词、字段范围、否定语境识别和结果高亮。
- 数据归档与导出：按月归档 SQLite 数据，并支持 CSV、JSONL 导出。
- 零第三方依赖：Python 3.9+ 即可运行，无需安装额外包。

## 项目结构

```text
.
├── sdgun_crawler.py       # 命令行爬虫、解析器与 SQLite 存储
├── web_app.py             # 本地 Web 服务与数据 API
├── web/                   # Web 控制台静态资源
├── start_web.bat          # Windows 一键启动脚本
├── desktop_app.py         # 桌面窗口及 Python 服务生命周期托管
├── .exe/                  # Windows 成品及桌面构建依赖
├── packaging/             # PyInstaller 生成的打包配置（构建时创建）
├── samples/captured/      # 本地抓取的 HTML、JSONL 与页面脚本样本
├── tests/                 # 自动化测试
│   └── fixtures/          # 本地测试数据库
└── data/
    ├── main/              # 当前运行主数据库及 WAL/SHM
    └── archive/YYYY/MM/   # 按发帖月份生成的 SQLite 归档
```

`data/main/sdgun_market.db` 是当前运行库；`data/archive/` 是按月归档。程序生成的
`*.db`、导出文件、样本和缓存属于本地数据，默认不会提交到 Git。

面向按数字 `tid` 排列的帖子页。程序按网站原生分类字段识别交易区 `fid=176` 的帖子：
`typeid=101/102/103/104` 分别对应“商家广告 / 二手出售 / 召集团购 / 求购”。
详情页内嵌数据不返回 `typeid`，因此详情抓取严格确认 `fid=176` 后，再以网站生成的
标题类型标签回退判断。非目标页不会进入正文、图片、评论或趋势处理。
列表中 `is_top=1` 的固定展示位会被排除，包括
`【二手出售】交易区准则ver.2022` 和置顶商家广告。普通商家广告会归入独立类型，
不会混入默认的二手出售视图。

## 快速使用

Python 3.9+，无第三方依赖：

```powershell
# 可选：先确认环境和运行测试
python --version
python -m unittest discover -v

# 启动本地 Web 控制台
python web_app.py

# 倒序扫描一段新 tid；结果写入 SQLite，命中帖同时输出到终端
python sdgun_crawler.py scan --start 4010000 --end 4009000 --workers 16

# 只保留包含任一关键词的帖子，并导出本次命中
python sdgun_crawler.py scan --start 4010000 --end 4009000 -k 锦明 -k 波箱 --jsonl latest.jsonl

# 已扫描过的 tid 默认跳过；需要重新检查（例如刷新“已出”状态）
python sdgun_crawler.py scan --start 4010000 --end 4009000 --no-new-only

# 从数据库生成分类、热门物品词和最新帖子摘要
python sdgun_crawler.py report --limit 1000 --top 30

# 从已知最新帖子之后持续监控；后续启动自动从数据库游标续接
python sdgun_crawler.py watch --start 4148800
```

查看完整命令参数：

```powershell
python sdgun_crawler.py --help
python sdgun_crawler.py scan --help
python sdgun_crawler.py watch --help
python web_app.py --help
```

## Web 可视化控制台

双击 `start_web.bat`，或运行：

```powershell
python web_app.py
```

然后打开 `http://127.0.0.1:8765`。控制台提供市场总览、供需趋势、交易状态、
价格带、热门物品词、活跃发布者、最新帖子、详情查看、多关键词检索、增量同步、
任务停止以及 CSV/JSONL 导出。

同步控制区可选择 4、8、16、24 或 32 个并发线程，默认使用 16 线程；选择会保存在
当前浏览器中。论坛帖子详情目前仅允许内地 IP 访问；请在符合站点规则的内地网络环境中
运行采集。若只是普通限流或网络不稳，请降低线程数。
论坛列表固定使用较稳定的 50 条分页，并使用独立的 12 秒超时与一次重试；二手帖 Wap
详情若返回 `cURL error 28` 或超时，
会自动改用论坛公开的 ViewPage 详情入口，不会把单个入口故障直接当作验证失败。
同步时还可选择只拉取二手出售、求购、召集团购、商家广告之一，或拉取全部类型；
未选择的类型会在解析正文和评论前跳过。以后切换到该类型时，系统会自动补抓此前因
类型筛选而跳过的 TID。最新帖子默认显示二手出售，侧边栏可切换类型或查看全部。

### Windows 桌面版（关闭窗口即停止 Python）

安装桌面构建依赖后，直接使用 PyInstaller 打包 `desktop_app.py`：

```powershell
python -m pip install -r .exe/requirements-desktop.txt
python -m PyInstaller --noconfirm --clean --onefile --windowed --name SDGun-Market --distpath .exe --add-data "web;web" --collect-all webview desktop_app.py
```

产物位于：

```text
.exe\SDGun-Market.exe
```

`SDGun-Market.exe` 直接包含桌面入口、Python 服务和网页资源，不经过 BAT，也不要求
目标电脑预装 Python。关闭桌面窗口后，本地服务、市场猎手和正在执行的采集任务都会停止，
不会继续留在后台。数据库保存在 EXE 同目录的 `data/main/sdgun_market.db`；迁移时请
同时复制整个 `data` 目录。

开发时可先直接运行桌面入口验证：

```powershell
python -m pip install pywebview
python desktop_app.py
```

原有的 `start_web.bat` 和 `python web_app.py` 仍是普通浏览器模式；浏览器自身没有可靠的
“最后一个标签页关闭”通知，因此该模式下服务需要在终端按 `Ctrl+C` 停止。

搜索框支持使用空格、逗号、顿号或分号分隔多个关键词；可选择“部分命中”（任意词）或
“全部命中”（每个词都必须出现），并可把检索范围限定为全部内容、仅标题或仅作者。
检索结果提供“快速定位”：打开帖子后会在标题、作者、正文、物品明细和评论中高亮关键词，
并自动滚动到第一个命中位置。
“全部内容”检索不会读取图片地址、帖子链接或闲鱼链接中的文字。类似“不含手电／不带手电／
没有手电”的否定语境仍保留在结果末尾，但使用灰色删除线和“排除”标记，不算作正常命中。

“市场猎手”以任务方式运行，每个猎手都有独立名称、规则、状态、结果和停止控制，可同时执行多个
猎手任务。任务以点击启动的时间为追踪起点，启动前的帖子只用于建立历史基线，不显示、不计入命中、
也不提醒。任务可随时编辑名称、规则和检查间隔，默认间隔为 60 秒；尚未命中时不会显示空的结果区域。
每个任务按自定义间隔自动增量刷新并检索；新帖命中或任务结束时会显示页面提醒，并在用户
授权后发送浏览器系统通知。任务状态会持久化到数据库旁的 `hunter_tasks.json`；主进程重新启动后，
此前仍在运行的任务会自动恢复并立即同步。任务也可永久删除。最短间隔为 10 秒，停止或删除单个猎手
不会影响其他猎手、普通刷新和数据库内容。

帖子默认按照论坛的实际 `created_at` 倒序排列，不使用爬取时间排序。系统持久保存
`last_recorded_id` 和列表同步时间；每次打开页面或点击“刷新最新”，分页调用玩具交易区
（fid 176）的公开帖子列表，直接读取 `tid/fid/typeid/is_top/create_time`。程序先在列表
层排除置顶与未选类型，只对新发现且被选中的帖子请求详情，不再逐个探测两个 TID 之间的
全站编号。旧版 `skipped_title` 也通过论坛列表批量重建类型，不再逐帖补探。
后台同步不请求评论，也不准备图片或视频；帖子行进入浏览器可见区域附近时，前端以最多
2 条并发预取该帖评论、媒体信息和前 3 张图片。未滚动到的帖子不请求，打开可见帖子时
通常已可直接读取本地缓存。
新发现且发布时间晚于本次打开时间的帖子会显示 `NEW`。

### 每日盘数据

系统以 `Asia/Taipei` 自然日（00:00:00–23:59:59）为一个盘，并将结果持久保存到
SQLite 的 `daily_market` 表。每盘量化保存：首末 TID、首末发帖时间、总发帖量、
出售/已出/求购/待确认数量、公开售出率、活跃用户、物品条目、价格样本数、均价、
中位数、最低价、最高价、标价合计、评论、图片、闲鱼链接、热门物品词、活跃发布者、
发帖量日环比和中位价日环比。面板可直接查看，并通过“导出日盘 CSV”下载完整日线。

每日盘同时计算 0–100 的“市场恐惧指数”：价格压力（中位价环比下跌）占 35%，
供给失衡（出售侧条目相对求购的占比）占 30%，放量冲击（发帖量环比上升）占 20%，流动性压力
（公开售出率的反向值）仅占 15%。由于卖家可能不会及时把成交帖标为“已出”，售出率只作为
弱信号，避免“未更新状态”被直接误判成市场恐惧。指数分为极度贪婪、贪婪、中性、恐惧、极度恐惧五档；
供给、成交状态和放量分项均相对前 30 个市场日的滚动中位数计算，历史不足 3 天时保持中性 50，
避免冷启动和出售区固有结构造成极端误判。价格压力在至少 5 个历史价格变化样本后同时参考历史
百分位。系统另给出反向的“市场综合指数”、1 日变化、7/30 日均线、三日趋势（改善/横盘/走弱）
以及由当日样本量和历史基准覆盖度共同决定的置信度；完整字段可从日盘 CSV 导出。

趋势图以青色实线表示市场综合指数、红色实线表示恐惧指数、黄色虚线表示市场指数 7 日均线，
三者统一使用 0–100 刻度，50 为中性。置信度的原始样本分由当日帖子充分度
`min(帖子数 / 20, 1) × 70` 与明确价格样本充分度 `min(价格样本数 / 10, 1) × 30`
组成，再乘以历史覆盖修正 `0.7 + 0.3 × min(历史基准日 / 14, 1)`。面板会直接标注当日
帖子数、价格样本数、基准日数和最终置信度来源。

帖子同时按实际发帖时间归档到 `data/archive/YYYY/MM/market.db`，磁盘文件夹最小分到月份；
月库内部使用 `post_day` 区分具体日期并建立日期索引。`data/main/` 主数据库保留全局游标、扫描状态
和面板运行索引，月库用于按年月归档管理，不为每天创建零碎数据库文件。

首次使用时应把区间改成当前实际的七位数 `tid`。建议倒序扫描，`--end` 小于
`--start`。稳定后按上次最高 `tid` 向上扫描即可。默认 16 并发、6 秒超时、不重试；
网络不稳定时加 `--retries 1`，服务器出现限流时降低 `--workers`。

长期运行推荐 `watch`。它每轮并发探测一小段全站新 `tid`，只有检测到更高编号已经
存在时才把中间空号视为历史缺口；位于最前端、尚未发布的编号不会写成永久已扫描，
下一轮仍会检查。按 `Ctrl+C` 会保存 `watch_cursor`，再次运行无需提供 `--start`。
可用 `--poll 30 --batch 16 --workers 8` 调低站点压力；`--cycles 1` 可做单轮测试。

## 输出字段

每个命中帖包含：`tid/url/title/username/user_id/created_at/content/images/videos/links/`
`xianyu_links/comments/category/is_sold/items/item_details/prices`。其中：

- `images` 只来自帖子内嵌正文和 `row.pics`，不扫描整页 `<img>`，不会混入头像、广告、等级图标；帖子行接近可见区域时解析图片 URL，并预取前 3 张供详情快速显示。
- `videos` 来自正文的 `<video src>` 及其嵌套 `<source src>` 标签，支持常见的 `data-src` / `data-original` 懒加载属性；视频 URL 同时保留在 `links` 中。
- 评论分页接口只对进入可见区域附近的帖子调用，最多 5 页；评论正文中的闲鱼、淘宝短链等会进入 `links`，已识别的闲鱼链接同时进入 `xianyu_links`。
- `item_details` 按空行、编号/项目符号和“一行一件明盘价”拆分，每件物品分别保存状态与价格。
  多物品帖只有部分物品售出时，帖子状态为 `部分已出`；无物品指向的笼统“已出”评论不会把整帖全部标成已出。
- 同一帖子同时含出售与求购物品时，帖子级状态默认归入 `出售`，标题下仍分别列出出售与求购物品。
- 价格只有带 `￥/¥/元/块/包邮` 等价格语境时才提取，不把日期、型号或数量误判为价格。
- SQLite 的 `scan_state` 保存所有访问结果，`posts` 只保存目标帖子；WAL 模式支持高吞吐写入。

## 效率策略

1. Web 同步先批量读取交易区列表中的原生分类字段，不再逐个探测全站 TID。
2. 只对用户选中的类型请求帖子 HTML；未选类型仅记录列表元数据。
3. 后台同步不请求评论、图片和视频；列表只预取可见区域附近的帖子，最多 2 帖并发、每帖 5 页评论和前 3 张图片。
4. 规则分类与趋势词频均在本地完成，不调用大模型或图片识别。
5. `--new-only` 默认开启，避免重复请求已经扫描过的无关 tid。
6. 帖子列表不预载缩略图；打开详情时才懒加载帖子图片，点击复用同一图片在页面内放大。

## 访问边界与 robots 检查

2026-07-20 实测访问 `http://app.sdgun.com.cn/robots.txt`，站点返回
`{"success":false,"msg":"module not exists:robots.txt","code":0}`，即当前没有可读取的
robots.txt 规则文件。这不等于站点授予无限制抓取许可，仍应控制并发并留意站点规则变化。

本工具只读取无需登录即可访问的公开帖子页及其公开评论接口，不包含登录、Cookie 注入，
也不会绕过地域或其他访问控制。请控制并发并遵守站点条款及当地法律。
